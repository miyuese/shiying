02项目概述

2.1 背景与定位

面向内容创作者的网页图片 AI 工具，从零自研（Chrome 扩展，无后端依赖）。核心价值一句话：「在任意网页上，把一张好图变成属于你的新图」——识别图中灵感（反推提示词）、换脸、按参考重绘、拍一套，并把过程沉淀为本地素材。

2.2 目标用户

  • 内容创作者 / 自媒体人：需要灵感复刻、人像素材创作
  • 设计师与运营：需要快速生成风格化配图
  • AI 绘画爱好者：需要高质量人脸参考与提示词工作流

2.3 范围

本版本做（MVP）：
  • 网页悬浮双按钮（打开插件 / 收集图片）+ 弹窗快捷入口 + 侧边栏工作台
  • 人物卡（上传建模、多卡管理、默认卡）
  • 三大生成功能：直接换脸 / 反推+双参考重绘 / 拍一套（2×2 四宫格）
  • 反推提示词展示与编辑、结果区（再生成/下载/存相册/复制 prompt）
  • 极简本地相册（收集 + 生成记录）
  • 自定义 API 设置（反推/生图分开配，支持 Base URL / Key / 模型名）
本版本不做：
  • 账号体系 / 积分计费 / License 授权
  • 多 Provider 目录化适配（仅 gpt-image 系列 + 任意反推模型）
  • 背景图识别（仅 <img>）、人脸圈选、语义搜索、多语言、云端同步
  • 水印功能（用户明确不要，保生成质量）

2.4 成功指标（MVP 阶段）

指标目标衡量方式
反推成功≥ 90%反推请求无错误返回率
生图成功≥ 80%生成任务最终产出图片率（含重试）
全链路耗时单次反推 < 15s从点按钮到出 prompt
崩溃/报错无未捕获异常SW / content 控制台无红色报错

03用户与核心场景

场景 1 · 反推 + 双参考重绘（核心闭环）

用户刷到一张喜欢的图 → 悬停点「打开拾影」→ 工作台里点「反推」→ 得到可编辑的中文提示词 → 选一张人物卡（人脸参考）→ 点「生成」→ 得到「保持原图构图、换成自己/指定人脸」的新图 → 下载或存相册。

场景 2 · 直接换脸

用户想把自己换进某张照片 → 选源图 + 选人物卡 → 点「换脸」→ 得到自然融合的换脸图。

场景 3 · 拍一套写真

用户有一张满意的生成图 → 点「拍一套」→ 得到同一人物四格写真（2×2）→ 下载或继续处理。

04功能需求详述

4.1 网页悬浮层（content script）

功能描述

在任意网页的 <img> 图片上悬停时，图片右上角弹出两个按钮：「① 打开拾影」「② 收集」。

交互流程

  1. 用户鼠标进入 <img> 可视区域 → 启动 300ms 定时器（防误触）
  2. 定时器到期且鼠标仍在图片上 → 注入按钮浮层（不修改 DOM 结构，仅挂载 shadow/绝对定位层）
  3. 点「打开拾影」→ 打开弹窗快捷操作（把当前图带入弹窗）
  4. 点「收集」→ 发送 image-collect 消息 → 成功 toast「已存入相册」；重复收集提示「已在相册中」
  5. 鼠标离开图片/页面滚动 → 移除浮层

边界与约束

  • 不注入：chrome://、Chrome Web Store、file://（MV3 自动限制）
  • 浮层不拦截图片点击（pointer-events 控制，按钮区域除外）
  • 同一时刻只允许一个浮层；避免与页面自身 UI 冲突（使用最高 z-index + 隔离样式）
  • 图片 URL 归一化（去重键 = URL + 页面 URL）

验收

在主流网站（微博/小红书/B 站/淘宝）悬停可用；快速划过不误弹；收集 2 次同一图提示去重。

4.2 弹窗（popup）

功能描述

点工具栏图标弹出 320×420 小窗：当前页图片快捷操作 + 最近任务状态。

  • 若从悬浮层「打开拾影」进入：自动载入该图片，展示「反推 / 换脸 / 拍一套 / 收集」四个快捷动作
  • 显示最近 3 条任务状态（生成中/完成/失败）
  • 「打开完整工作台」按钮 → 唤起侧边栏（side panel）
  • 「设置」入口

4.3 侧边栏工作台（side panel · 主界面）

布局（自上而下）

  1. 顶部栏：Logo「拾影」+ 连接状态点（Key 未配=黄，已配=绿）+ 设置入口
  2. Tab 栏：反推重绘换脸拍一套相册人物卡
  3. 内容区：当前 Tab 视图
  4. 底部全局：结果区（生成结果卡片，常驻）

通用组件

  • 图片选择器：来源切换（网页收集图 / 相册 / 上传文件），带缩略图网格
  • 人物卡选择器：下拉/卡片列表，默认选中「默认卡」
  • 任务状态条：loading 动画 + 进度文案 + 失败重试按钮
  • 结果卡片：大图 + 操作条（再生成 / 下载 / 存相册 / 复制 prompt / 拍一套）

4.4 功能 B · 反推 + 双参考重绘（核心）

输入输出

  • 输入：构图参考图（= 反推来源图，必选）+ 人脸参考图（从人物卡选，必选）
  • 输出：反推中文提示词（可编辑）+ 生成结果图

详细流程

  1. 选输入图（网页收集/相册/上传）
  2. 点「反推」→ 调反推模型 → 返回提示词 → 展示在编辑框（可编辑）
  3. 选人物卡（人脸参考）——可选「不选人脸，纯反推」模式
  4. 点「生成」→ 调生图模型（构图=输入图 + 人脸=人物卡 + prompt）→ 任务进行中
  5. 成功 → 结果进结果区 → 可下载/存相册/拍一套

提示词定义

⚠ 重绘 ≠ 换脸，两者指令不同：

换脸（功能 A）重绘（功能 B）
目标在已有源图上换脸，其他全不变生成一张全新图，参考构图+人脸
指令模板自研换脸模板
「以图2作为唯一基础图…严格保留图2的一切…只换脸」		反推配方 + 重绘使用说明（见下）
「根据提示词生成新图，构图参考图指导布局/场景/光线，人脸参考图指导人物身份」
图2（构图参考）源图 = 保持不变的底图构图参考图 = 生成参考，不是底图
图1（人脸参考）人物卡 = 替换进去的脸人物卡 = 生成人物的容貌来源
关键区别换脸模板说「严格保留图2的一切」重绘不保留任何图，是全新生成

反推：使用反推方案合集（默认「通用快速反推」），由用户在设置中选择方案。

换脸指令：使用自研换脸模板（双图分工）——以源图为「图2」（唯一基础图，保持不变），人物卡为「图1」（脸部身份来源），prompt 字段 = 反推配方 + 换脸模板。

重绘指令：prompt 字段 = 反推配方（用户可编辑）+ 重绘使用说明。说明借鉴换脸模板的「双图分工」思路，但不是其原文——因为换脸模板说「以图2作为唯一基础图，严格保留图2的一切」，而重绘是全新生成。重绘使用说明定义为：

根据以下提示词生成一张全新的图片。 构图参考图（= 反推来源图）作为画面布局、场景、构图、镜头角度、光线环境和色彩氛围的参考——但不是底图，最终结果应是全新画面，而非在参考图上修改。 人脸参考图（= 人物卡）作为人物面部身份的来源。生成图片中的人物面部特征（脸型、五官、骨相）应与人物卡一致，但需自然适配新画面的姿态、光线和表情。 提示词（反推配方，用户可编辑）： ━━━━━━━━━━━━━━━━━━━━━━━━━━━━ [此处插入反推出的提示词，用户可编辑] ━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 要求：高保真保留人脸参考图的人物识别度，自然融合到提示词描述的场景中。不要贴脸感，肤色和光影适配新场景而非照搬任一参考图。

4.5 功能 A · 直接换脸

  • 输入：源图（相册/收集/上传）+ 人物卡（人脸）
  • 流程：选图 → 选卡 → 点「换脸」→ 生成 → 结果区
  • 提示词：自研换脸模板（图2=源图、图1=人物卡）
  • 失败处理：源图无清晰人脸 / 人物卡无效 → 明确报错提示

4.6 拍一套（2×2 四宫格）

  • 输入：参考图（通常是刚生成的结果/相册图）+ 人物卡（默认继承当前）
  • 流程：选图 → （选卡，可默认）→ 点「拍一套」→ 生成 2×2 大图 → 本地切分为 4 张 → 结果区展示 4 张 + 原大图
  • 提示词：自研拍一套英文模板（一致性最高优先级）
  • 切图：canvas 按中心十字裁切 4 块，保留各格独立下载

4.7 人物卡

  • 上传 1~4 张人物照片 → 生成标准三视图人物卡（自研模板，16:9）
  • 命名、设为默认、删除
  • 图片本体存 IndexedDB（blob），元数据存 storage.local
  • 上限：建议 20 张（防存储膨胀，可在设置调整）

4.8 极简相册

  • 两类条目：收集（kind=collect，带来源页面 URL）、生成记录（kind=generate，带 prompt / 模型）
  • 操作：网格浏览、删除、选中作为生成输入、下载原图
  • 分页：每次加载 50 条，滚动加载
  • 图片本体存 IndexedDB，元数据索引存 storage.local

4.9 结果区（全局底部）

  • 显示最近一次生成结果（最多 4 张）
  • 操作：再生成（同参数重新生成）/ 下载 / 存相册 / 复制 prompt / 送去拍一套
  • 生成中显示进度与取消按钮（AbortController）

4.10 设置页（options）

反推配置（reverseApi）

  • Base URL（默认 OpenAI 官方 https://api.openai.com/v1，可改中转）、API Key、模型名（如 gpt-4o-mini）

生图配置（generateApi）

  • Base URL、API Key、模型选择（gpt-image 系列，或自定义模型名）

通用

  • 「测试连接」按钮：对反推/生图分别发最小请求验证 Key
  • 反推方案选择（默认「通用快速反推」）
  • 默认人物卡、默认画幅
  • 免责声明 + 隐私说明（换脸风险、图片上传第三方 API）

4.11 首次引导

  • 安装后打开工作台：若任一 Key 未配 → 顶部黄条「请先完成 API 配置」+ 跳转设置按钮
  • 设置页首访：展示 2 步引导（填反推 → 填生图 → 测试连接）
  • 所有空态（相册空/人物卡空）提供「去配置/去上传」指引

4.12 任务与错误处理（横切）

任务模型

  • 每个生成动作 = 一个 Task：{id, type, status, inputs, result, error, createdAt}
  • 状态机：pending → running → done | failed（支持 cancel → cancelled）
  • Task 持久化到 storage.local —— 防止 MV3 Service Worker 休眠导致状态丢失

错误码与用户提示

场景用户提示
Key 无效 / 401「API Key 无效，请到设置检查」
余额不足 / 429「额度不足或请求过快，请稍后重试」
图片超尺寸「图片过大，已自动压缩」/ 失败则提示上传更小图片
防盗链抓取失败「该图片无法直接读取，请截图或下载后上传」
异步任务超时「生成超时，可在任务列表重试」
网络错误「网络异常，请检查网络后重试」

05非功能需求

类别要求
性能工作台首屏 < 1s；图片预处理（压缩/降采样）< 500ms；悬浮层无卡顿
并发同一时间仅 1 个生成任务（串行队列），可排队
安全API Key 仅存 storage.local、仅在 background 使用，绝不进入 content/页面；输入 HTML 全部转义防 XSS
隐私设置页明示「图片将上传你配置的 API 服务商」；不采集任何使用数据
兼容Chrome ≥ 114（side panel API）；主流网站悬浮层可用
可维护TS 严格模式；消息协议有类型定义；核心逻辑有单元测试

6.6 状态管理

  • 工作台：轻量「单例 store + 订阅」模式（无 Redux 类依赖），Tab 切换/选择/结果均为可订阅状态
  • 跨端状态（任务进度）：background 持有唯一任务队列，变更后向所有连接的端口广播 task-changed
  • content 与 panel 用 chrome.runtime.connect 长连接（name: shiyin-workbench）接收广播

07技术栈详述

一句话总览：TypeScript（类型安全） + Vite（构建/热更新） + 原生 Web API（无重型框架） + Vitest（测试）。全项目无后端，仅调用用户配置的自定义 AI API。

7.1 语言：TypeScript（严格模式）

用途具体
消息协议用 union type 定义全部消息，router 的 switch 分支自动补全、传参错编译期报错
数据模型Settings / PersonCard / AlbumItem / Task 全类型化，跨端共享（shared/types.ts）
API 响应反推/生图响应定义类型，避免运行时字段拼写错误
tsconfigstrict: true，noUncheckedIndexedAccess 等全开

7.2 构建：Vite + 自定义 manifest 插件

项说明
多入口background / content / panel / popup / options 五个入口，各自打包
manifest 生成manifest.config.ts 写 Vite 插件，构建时按环境注入 version/名称/图标，输出 dist/manifest.json
content 隔离content script 打包为 IIFE（不设 type=module），避免与页面冲突；样式注入用隔离 class 前缀
热更新开发模式 vite dev + chrome.runtime.reload() 辅助脚本，改码即刷新
产物dist/ 直接「加载已解压的扩展程序」

7.3 UI 方案：原生 TS + 组件函数（不引 React/Vue）

决策理由
不引框架扩展 UI 页面规模小（5 个 Tab + 表单），框架会引入构建复杂度与体积；原生 TS + 模板字符串 + 事件委托足够
组件化写法每个视图导出 render(container, state) => cleanup() 函数；状态变化时局部重渲染，配合事件委托减少监听器
样式手写 CSS（CSS 变量统一主题色）；content 悬浮层用 shadow DOM 隔离页面样式
升级路径若后续 Tab 状态复杂度上升，可平滑引入 Preact（~4KB）——架构上组件函数即兼容

7.4 存储：chrome.storage.local + IndexedDB

  • shared/utils 提供 Promise 化封装；IndexedDB 用原生 API + 薄封装（避免额外依赖）
  • 图片一律先压缩（canvas 降采样到 ≤ 2048px、JPEG/WebP 质量 0.9）再入库，控制存储与上传体积

7.5 网络：background 内 fetch（仅在 background 发起）

  • 所有 API 调用集中在 providers/，content/panel 一律通过消息间接调用 —— 保证 API Key 不泄露到页面
  • 请求统一带 AbortSignal（支持取消）与超时（15s 反推 / 120s 生图首响应）
  • 异步生图：若服务商走异步任务（提交 → 轮询），封装 pollTask(url, interval, timeout)

7.6 测试：Vitest

  • 纯逻辑全测：prompts 组装、消息类型、图片工具（切图/压缩）、任务状态机
  • API 层用 fetch mock（vi.stubGlobal）测请求体正确性
  • 目标：核心逻辑覆盖率 ≥ 70%

7.7 工程质量配套

  • ESLint + Prettier：统一规范（typescript-eslint recommended）
  • husky + lint-staged：提交前自动 lint
  • Git：main + feature 分支，每个里程碑一个 tag

08API 对接规格

8.1 反推（视觉理解）—— OpenAI 兼容 chat/completions

POST {reverseApi.baseUrl}/chat/completions { "model": "gpt-4o-mini", // 用户配置 "messages": [{ "role": "user", "content": [ { "type": "text", "text": "【系统提示词】" }, // 来自反推方案合集（用户选择 profileId） { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } } ] }], "temperature": 0.7, "max_tokens": 1200 }

响应取 choices[0].message.content。系统提示词来源：src/shared/prompts.ts 内嵌反推方案（默认「通用快速反推」，可选「人像通用详细」等）。

8.2 生图（gpt-image 系列）—— OpenAI 兼容 images

两种能力：编辑（带参考图）与生成（纯文生图）。拾影全部带参考图，主走 edits。

POST {generateApi.baseUrl}/images/edits // multipart/form-data image: 构图参考图（源图，二进制） prompt: 提示词（含人脸/场景指令） model: gpt-image 系列 // 用户配置 size: "1024x1024" | "1024x1792" | ... // 按画幅映射 // 若服务商支持多图输入（部分中转支持），附加： image2: 人脸参考图（人物卡） // 不支持多图的场景 → 拼图法（fallback）： // 在发送前把人物卡人脸缩放贴到源图右下角（50px 角标）， // prompt 注明「右下角小图为人脸参考，请将其身份用于主图」

提示词来源（自研模板，定义见 src/shared/prompts.ts）： 换脸换脸模板（图2=源图作底图不变，图1=人物卡换脸）—— prompt = 反推配方 + 换脸模板全文
重绘反推配方（用户可编辑）+ 重绘使用说明（借鉴换脸模板双图分工思路，但指令是「全新生成」而非「保留源图」——详见 4.4 节）
拍一套拍一套英文模板（一致性最高优先级）
人物卡人物卡三视图模板

8.4 测试连接

  • 反推：发一条 max_tokens: 8 的最小 chat 请求（纯文本）
  • 生图：发一条 images/generations 最小请求（或仅检查 401/403）
  • 结果分级：ok / 401 无效Key / 403 无权限 / 404 模型或端点不支持 / 其他，各自给中文提示

09核心数据流

9.1 反推 + 双参考重绘（时序）

panel 选图 → analyze-image 消息 → bg.providers/analyze.ts 调 chat/completions → 返回提示词 → panel 编辑框（用户可改）→ panel 选人物卡 → generate-image 消息(taskType=redraw) → tasks.ts 建任务(持久化) → providers/generate.ts 预处理(压缩+拼图) → 调 images/edits → 轮询/等待 → 结果写 IndexedDB → 广播 task-changed → panel 结果区渲染 → 用户下载/存相册

9.2 换脸（时序简版）

选源图 + 选卡 → generate-image(taskType=faceswap) → 同 9.1 生图链路（人脸=人物卡，构图=源图）→ 结果区

9.3 拍一套（含切图）

选图 + (选卡) → generate-image(taskType=suite) → 生成 2×2 大图 → 前端 canvas 按中心十字切 4 块 → 4 张单图 + 原大图入结果区/相册 → 可逐张下载

9.4 任务持久化与恢复（防 SW 休眠）

任务创建即写 storage.local(tasks) → 执行中每步更新 status → SW 被休眠唤醒(onStartup) → 扫描 running 任务 → 若服务商支持查询则续查，否则标记 failed+可重试 → 广播恢复结果

12风险与合规

  • 中转站兼容性：images/edits 的 multipart 多图支持不一 → M6 真实验证；拼图法作为兜底
  • 换脸效果：依赖模型理解 → 提示词按自研换脸模板，必要时调措辞
  • API Key 安全：仅 background 持有；提示用户勿分享扩展备份
  • 合规：学习用途；换脸功能含免责声明；不上传他人私密照片
  • 提示词版权：提示词模板为自研成果，仅本项目内部使用
  • 权限最小化：<all_urls> 是悬浮层必需；商店审核时准备说明文案

13MVP 验收标准

  1. 扩展可在 Chrome 加载，工具栏图标 + 侧边栏 + 弹窗 + 设置页全部可打开
  2. 未配 Key 有引导；配置后测试连接反馈正确
  3. 网页悬停 出双按钮，收集去重生效，相册可浏览/删除
  4. 人物卡可建/选/删/设默认
  5. 反推成功且提示词可编辑；换脸/重绘/拍一套三种任务均能出图并下载

  7. 控制台无未捕获异常；核心逻辑单元测试通过
